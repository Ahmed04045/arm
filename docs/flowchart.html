How the agent network works

Sensor readings travel from the beds to the laptop, where 16 AI agents in four departments check them against the crop's ranges. The answer goes back to the ESP32 as a status colour, a ranked list of actions and a short briefing.

The full loop

Green is the EZFarm hardware and firmware, which stays unchanged. Magenta is the agent network on the laptop.

Inside the agent network

One run per node, compiled from quars_amaranth_network.json into a LangGraph. Agents inside a department run at the same time. An arrow into a box that has several arrows means it waits for all of them.

How often each part runs

10 s
Nano → ESP32

Each node sends all six readings over RF. The gateway checks its own ranges, sets the LEDs and publishes the readings to MQTT.

60 s
Rule-checked run

The bridge averages the last minute for each node and runs all 16 agents. Status, departments and actions are refreshed in milliseconds.

06:00 · 18:00
Briefing (or on request)

Adds the Market & Strategy department (Qatar prices, crop fit by season, profitability, web research). The Director writes "Today" and "Opportunity". Questions are answered any time.

What the ESP32 receives

All retained, so the ESP32 gets the latest answer the moment it connects. Full payloads and an Arduino snippet are in ESP32_INTEGRATION.md.

Who decides what

Rules decide

Status colours, LEDs and commands come only from checking readings against the team's A. cruentus ranges. Outside the ideal band is a warning. Outside the tolerated band is critical.

Models explain

LLMs write briefings from facts the rules have already checked, and only mention sensors that are installed. The farm-qwen diagnosis is shown as advice and never switches anything.
